FreePremium — Production Deploy Guide

Stack: GitHub → Vercel (Next.js app) → Neon or Supabase (free Postgres) → Cloudflare (domain DNS)

Audience: Client / operator — follow every step in order. No coding experience required beyond copy/paste.

Outcome: Live site at https://yourdomain.com with admin panel, database, HTTPS, and automatic deploys from GitHub.

Adult site · 18+ · Keep admin secrets private
Important: FreePremium is one full-stack Next.js app. Do not put “frontend on Netlify” and “backend elsewhere.” Use Vercel for the whole app and Postgres (Neon or Supabase) for the database. SQLite files do not work on Vercel’s serverless filesystem.

Time estimate: 45–90 minutes the first time if accounts already exist.
You need: a computer, email, domain name, GitHub access to the FreePremium repo (or a zip from your developer), and a password manager recommended.

1. Accounts to create (do this first)

  1. GitHub — https://github.com/signup
  2. Vercel — https://vercel.com/signup (sign up with GitHub)
  3. Neon — https://neon.tech or Supabase — https://supabase.com (pick one database)
  4. Cloudflare — https://dash.cloudflare.com/sign-up
Use a strong unique password for admin later. Never reuse your GitHub password as ADMIN_PASSWORD.

2. Get the code onto GitHub

Your developer should already have FreePremium in a Git repository. Choose A or B.

Option A — Developer already pushed the repo

  1. Open GitHub → find the FreePremium repository.
  2. Confirm you are a collaborator / owner.
  3. Copy the repo URL, e.g. https://github.com/YOUR_USER/freepremium.

Option B — Create a new GitHub repo and upload

  1. GitHub → New repository.
  2. Name: freepremium (or your brand name).
  3. Visibility: Private recommended (contains your business app).
  4. Do not add a README if the project already has files.
  5. Ask your developer to push the code, or use GitHub Desktop:
    • Install GitHub Desktop → File → Add Local Repository → choose the FreePremium folder.
    • Publish repository to your GitHub account.
Never upload the real .env file to GitHub. Only .env.example is safe. Secrets go into Vercel Environment Variables (Section 5).

3. Create the free Postgres database

Choose either Neon or Supabase — not both for the same site.

3A. Neon (recommended for Vercel)

  1. Go to https://console.neon.tech → Sign up / Log in.
  2. Click Create project.
  3. Name: freepremium. Region: pick closest to your audience (e.g. US East for USA traffic).
  4. Create project → open the project dashboard.
  5. Click Connect (or Connection details).
  6. Copy two connection strings:
    • Pooled connection → this becomes DATABASE_URL (often contains -pooler in the host).
    • Direct connection → this becomes DIRECT_URL (no pooler).
  7. Both should look like:
    postgresql://USER:PASSWORD@HOST/neondb?sslmode=require
Keep both strings in a password manager. You will paste them into Vercel soon.

3B. Supabase (alternative)

  1. Go to https://supabase.com/dashboard → New project.
  2. Set a strong database password (save it).
  3. Region: choose closest to users.
  4. Project Settings → Database → Connection string.
  5. Copy:
    • URI (Transaction pooler / Mode: Transaction) → DATABASE_URL
    • URI (Session / Direct) → DIRECT_URL
  6. Replace [YOUR-PASSWORD] with the real DB password if the UI shows a placeholder.
  7. Ensure strings include SSL (Supabase usually adds this automatically).

4. Create secrets you will need

Generate these on your computer before opening Vercel.

4.1 Session secret

On Mac / Linux / Git Bash / Windows (PowerShell with OpenSSL), run:

openssl rand -base64 48

Copy the entire output. That is SESSION_SECRET (must be 32+ characters).

If OpenSSL is missing on Windows, use any long random string (64+ random characters) from a password manager.

4.2 Admin login

VariableExample rules
ADMIN_USERNAMEYour private username (not “admin” if possible)
ADMIN_PASSWORDMinimum 10 characters, long & unique

4.3 Public site URL

Decide your final domain now, e.g. https://freepremium.com or https://www.freepremium.com.

Use the exact URL (with https://, no trailing slash) as NEXT_PUBLIC_SITE_URL.

You can temporarily use the Vercel URL first (e.g. https://freepremium.vercel.app), then change to the real domain after Cloudflare is set — then redeploy.

5. Switch the database to PostgreSQL (required before Vercel)

The developer copy may ship with SQLite for local testing. Vercel needs Postgres.
  1. Open prisma/schema.prisma.
  2. Find provider = "sqlite" and change it to provider = "postgresql".
  3. Optional but recommended for Neon — under url = env("DATABASE_URL") add:
    directUrl = env("DIRECT_URL")
  4. Commit and push this change to GitHub (or ask your developer to do it once).
  5. Use the Neon/Supabase URLs from Section 3 as DATABASE_URL / DIRECT_URL in Vercel.

6. Deploy on Vercel

  1. Open https://vercel.com/dashboard → Add New… → Project.
  2. Import the GitHub freepremium repository (authorize GitHub if asked).
  3. Framework Preset should detect Next.js. Leave Root Directory empty (repo root).
  4. Build Command (confirm): prisma generate && prisma db push && next build
    (This is already set in package.json — Vercel uses npm run build.)
  5. Output: leave default (Next.js).
  6. Install Command: npm install (default).
  7. Before clicking Deploy, open Environment Variables and add all of the following for Production (also add to Preview if you want preview links to work):
NameValue
DATABASE_URLNeon/Supabase pooled Postgres URI
DIRECT_URLNeon/Supabase direct Postgres URI
NEXT_PUBLIC_SITE_URLhttps://yourdomain.com (or temporary https://….vercel.app)
ADMIN_USERNAMEyour admin username
ADMIN_PASSWORDyour long password (10+ chars)
SESSION_SECRETopenssl random string (32+ chars)
Optional later: EMBED_ALLOWED_HOSTS, EMBED_ALLOW_ANY — only if your developer instructed you.
  1. Click Deploy.
  2. Wait 2–5 minutes. First deploy creates database tables via prisma db push.
  3. If it succeeds, open the *.vercel.app URL and confirm the homepage loads.
  4. Open https://YOUR-DEPLOY.vercel.app/admin/login and sign in with ADMIN_USERNAME / ADMIN_PASSWORD.

If the deploy fails

  • Prisma / DATABASE_URL errors → check both URLs, password encoding, sslmode=require, and that DIRECT_URL is set.
  • SESSION_SECRET / ADMIN_PASSWORD errors → production refuses weak/missing secrets. Lengthen them and redeploy.
  • Build timeout → retry once; free tiers can be slow on first build.
  • Open Vercel → Project → Deployments → failed deploy → Building logs → copy the red error to your developer if stuck.

7. Connect your domain with Cloudflare

This makes https://yourdomain.com open your Vercel site with free SSL.

7.1 Add site to Cloudflare

  1. Buy/own a domain (Namecheap, GoDaddy, Google Domains/Squarespace, etc.).
  2. Cloudflare Dashboard → Add a site → enter yourdomain.com.
  3. Choose the Free plan → Continue.
  4. Cloudflare scans existing DNS records → Continue.
  5. Cloudflare shows two nameservers, e.g.: 
    ada.ns.cloudflare.com
bob.ns.cloudflare.com
  6. At your domain registrar, replace the domain’s nameservers with Cloudflare’s two nameservers → Save.
  7. Wait until Cloudflare shows the zone as Active (can take 5 minutes to 24 hours; often under 1 hour).

7.2 Add domain in Vercel

  1. Vercel → your project → Settings → Domains.
  2. Add yourdomain.com and (recommended) www.yourdomain.com.
  3. Vercel shows the DNS records it needs (usually an A record for apex and CNAME for www).

7.3 Create DNS records in Cloudflare

Typical Vercel setup (confirm values shown in your Vercel Domains page — they can change):

TypeNameContent / TargetProxy status
A@76.76.21.21 (Vercel’s apex IP — use what Vercel displays)DNS only (grey cloud) or Proxied — see note
CNAMEwwwcname.vercel-dns.com (or the exact target Vercel shows)DNS only (grey cloud) recommended first
Proxy tip: For the first connection, set Cloudflare records to DNS only (grey cloud). After Vercel marks the domain as Valid / SSL ready, you may turn on Proxied (orange cloud) if you want Cloudflare CDN/WAF. If SSL loops happen, keep DNS only or set SSL/TLS mode to Full (not Flexible).

7.4 Cloudflare SSL/TLS settings

  1. Cloudflare → your domain → SSL/TLS.
  2. Set encryption mode to Full (recommended) or Full (strict) once Vercel cert is active.
  3. Do not use Flexible (causes redirect loops with Vercel).

7.5 Update site URL env and redeploy

  1. Vercel → Project → Settings → Environment Variables.
  2. Edit NEXT_PUBLIC_SITE_URL to https://yourdomain.com (no trailing slash).
  3. Deployments → … on latest → Redeploy (required so the new URL is baked into the build).

7.6 Verify

  • https://yourdomain.com loads the site
  • https://www.yourdomain.com redirects or loads correctly
  • Padlock / HTTPS works
  • https://yourdomain.com/admin/login accepts your admin password
  • https://yourdomain.com/sitemap.xml opens XML
  • https://yourdomain.com/robots.txt opens text

8. First-time site setup (after go-live)

  1. Login: https://yourdomain.com/admin/login
  2. Admin → Settings
    • Site SEO Title / Description / Keywords
    • Google Search Console verification code
    • Theme
    • Ad HTML slots (ExoClick / TrafficStars / etc.) — only paste trusted codes
    • Turn Ad preview mode OFF for real ads
  3. Admin → Categories / Performers / Videos — add or import content (CSV Maker supported).
  4. Google Search Console
    • Add property for https://yourdomain.com
    • Verify with the meta tag code from Settings
    • Sitemaps → submit:
      • https://yourdomain.com/sitemap.xml
      • https://yourdomain.com/sitemap-videos.xml

9. How updates work forever (no manual server)

  1. Developer pushes code to GitHub main/master.
  2. Vercel auto-builds and deploys.
  3. Database schema updates run during build via prisma db push.
  4. Your content (videos, settings) stays in Neon/Supabase — not wiped by deploys.
You do not need to SSH into a server for normal updates.

11. Security rules (read once)

  • Never post admin passwords in Discord/email screenshots.
  • Never commit .env to GitHub.
  • Only paste ad scripts from networks you trust (they run in visitors’ browsers).
  • Keep the site 18+ compliant (age gate is built-in).
  • Rotate ADMIN_PASSWORD + SESSION_SECRET if they leak → update Vercel env → Redeploy.
  • Cloudflare email routing / WAF optional later for protection.

12. Backups

  • Neon: Project → Backups / history (plan-dependent). Export SQL periodically for critical data.
  • Supabase: Database → Backups (plan-dependent). Use dashboard SQL export for snapshots.
  • Export important CSV of videos from Admin if you keep a manual inventory.

Empty site / no tablesConfirm build log shows prisma db push success; check DATABASE_URL

Images/embeds blockedAsk developer about EMBED_ALLOWED_HOSTS for new hosts
Free DB “paused”Neon free projects may sleep — first request wakes them (few seconds)

14. Go-live checklist

  • Code is on GitHub (private recommended)
  • Neon or Supabase project created; pooled + direct URLs saved
  • prisma/schema.prisma provider set to postgresql and pushed to GitHub
  • Vercel project imported from GitHub
  • All 6 env vars set on Vercel Production
  • First deploy succeeded (green)
  • Admin login works on vercel.app
  • Domain added in Vercel
  • Cloudflare nameservers active at registrar
  • A / CNAME records correct
  • SSL/TLS = Full
  • NEXT_PUBLIC_SITE_URL updated + redeployed
  • Homepage + /admin work on custom domain
  • SEO settings filled
  • Sitemaps submitted to Google Search Console
  • Ad preview mode off; real ads pasted
  • Secrets stored offline / password manager
